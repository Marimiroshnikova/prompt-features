MMLU-Pro miss prediction · Phases 4 to 6

Can prompt features predict when an LLM will be wrong?

Not yet. On 280 questions, no learned model beats the simple “this model on this subject” fail rate. The data is too small to tell a weak real signal from noise. About 1,000 questions would settle it, for roughly $21 in API calls.

What was wrong in the first notebooks

  • The regression split rows, not questions. All 145 test questions were also in training.
  • question_id was left in as a feature.
  • So its R² of 0.32 was optimistic: the model had seen every test question.

From here on, every test uses questions the model never saw. Question id and MMLU subject are never features; subject is only used as a baseline.

Phase 6 · metrics locked before testing

Which number decides depends on how the score is used

Product skips the riskiest X%

Only the order matters. A score that says 90% on hard questions and 80% on easy ones works perfectly.

Decide on: coverage–risk curve, error at 90 / 80 / 70% coverage, AURC.

Product uses a threshold or shows the number

“Skip if risk > 30%” only works if 30% really means 30%.

Decide on: Brier, Brier Skill Score, reliability diagram, ECE (15 quantile bins).

Always also reported: log loss (clipped to [1e−4, 1−1e−4]), AUROC, AUPRC next to its base rate, a question-level bootstrap interval, and results by model and by subject. RMSE only next to its noise floor. Brier Skill Score = 1 − Brier ÷ Brier of always guessing the average.

Phase 4 · H1 · coverage–risk

Skipping risky questions helps; the logistic ranks best when skipping a lot

At 80% coverage the XGBoost binary score leaves 18.6% errors, a drop of 1.8 points (95% CI [-3.4 pt, -0.1 pt]). The binary logistic is the same (18.7%); both soft scores' drops include 0. Skipping harder, the logistic ranks better: 15% error while still answering 55% of questions (XGBoost binary: 32%), and 10% error at 24% (XGBoost: 2%).

Phase 4 · H2 and reduced H3

Adding the model columns helps a bit; none reach the baseline

Prompt-only minus all features: XGB binary +0.0058 [+0.0028, +0.0087], logit soft +0.0018 [+0.0003, +0.0031]. Both intervals exclude 0: real, but small. The planned H3 cannot run: context window, temperature, top-p and output pressure are the same for all three models. Stand-in: prompt, then + model id, then + knowledge cutoff and recency gap.

What next

Grow the data, then rerun the same scripts

  1. Collect 1,000 questions (about 71 per subject) × the same 3 models × 10 answers. About 39,000 calls and roughly $21.
  2. Seal 20% of the questions first, with 25 answers each. Touch them only once, at the end.
  3. Rerun unchanged: run_h1.py, run_h2_h4.py, run_power.py, build_deck.py. Same metrics, same splits, same decision rule.
  4. For H3, add a second temperature on part of the set. Without it, model limits cannot be tested.

Promotion rule: a feature set counts only if its 95% interval beats model × subject on the sealed set, on the metric that matches how the product uses the score.
